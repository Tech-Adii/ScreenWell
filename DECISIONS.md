# ScreenWell engineering decisions

1. Electron + strict TypeScript + React + Vite. A Windows app, not a hosted website. The built UI is served through the secure local `screenwell://app` protocol. There is no production server.
2. SQLite lives in Electron's per-user AppData directory, with WAL and frequent transactional writes. Electron 45 includes Node's `node:sqlite`; this replaces `better-sqlite3`, whose native rebuild required absent Visual Studio tools. Built-in SQLite avoids native addon/ABI installation failures. Data is not encrypted; Windows account permissions provide isolation. No claims of encryption.
3. Camera is off on first run and every launch. Consent and camera activity are separate. Closing to tray stops camera capture. Numbers only are persisted; frames and landmarks exist only in memory.
4. All assets and MediaPipe models are bundled at build time. Internet access is permitted only for developer dependency/model acquisition, never for app operation.
5. The scheduler will run in Electron main so minimising the UI does not suspend timers. Quiet hours cross midnight. Focus mode will suppress all reminders.
6. A large reminder is an in-app card, never a screen lock or a focus-stealing full-screen window. Manual Important task mode handles exams and calls. Typing adaptation observes activity only inside ScreenWell; global input capture is deliberately excluded.
7. Windows binaries will be unsigned unless a signing certificate is supplied. Code signing and clean-machine, physical-camera, and performance checks are reported separately from automated checks.
8. Default hydration goal is a user-editable habit target, not a recommended medical intake. No health data is inferred from optional demographic answers.
9. PDF generation uses pdf-lib and a bundled Noto Sans font. An initial hidden Chromium print-window export stalled during integration testing; direct document generation is deterministic and avoids printer/render-window dependencies. CSV cells neutralise formula prefixes.
10. The wellness score uses breaks (weight 40, four completed pauses), water (weight 30, personal goal), observed posture (20), and observed blink rhythm (10, capped at 12/min as a project heuristic). Missing camera components are excluded, remaining weights normalised. It is not a health assessment.
11. Demo data is deterministic, synthetic, labelled in UI and exports, and held only in a separate in-memory SQLite database. It is never seeded into personal history.
12. No automatic full-screen app detection or global input capture. Manual Important task mode handles classes/exams. Typing deferral only observes timestamped activity inside ScreenWell. More complex personal learning remains deferred. Guided study planning was added in version 1.4.
13. Windows speech is used only when a voice reports `localService = true`; otherwise text remains available. A consistent English-first UI, local fonts, separate exercise content, and locale-aware date formatting prepare future translation work; additional languages are not shipped.
14. Final unsigned executable launch was rejected by the host's organization Device Guard policy (exit 4551). No policy or signing trust settings were changed to bypass that control. Source validation and intermediate smoke results are distinguished from final release execution, which requires approved signing or allowlisting on this managed host.
15. Version 1.1 defaults proximity alerts to ten continuous seconds, with a 125% face-scale trigger and separate 60-second distance cooldown. These are adjustable project defaults. Proximity is face-only; posture still needs visible shoulders.
16. Bundle Lite, Full and Heavy pose variants. Full at up to 6 FPS balances processing and detail; Heavy uses up to 5 FPS and Lite up to 8 FPS. Pose calibration is model-specific. The worker never queues frames when already busy.
17. Version 2 geometry uses shoulder-relative world depth, normalised neck length, shoulder slope and head angles. Stable four-second calibration, robust smoothing, hysteresis and quality checks reduce unreliable alerts. Old calibration units are not mixed with the new geometry.
18. Alert cooldown starts on delivery. Focus and camera snooze suppress evidence; missing or uncertain frames reset it. Renderer throttling is adjusted only while capture is active so monitoring continues behind other apps. Physical-user accuracy is not inferred from synthetic tests.
19. Guided-session hours count study only. Default 20-minute blocks and 30-second rests are project preferences, not clinical prescriptions. Exercise milestones use accumulated study minutes, so a 30-minute preference splits a 20-minute block around the exercise. The review shows the exact sequence and total elapsed time including resets.
20. Session blink, posture and optional distance choices are independent. Explicit session consent starts only the selected checks for calibration, without enabling global consent. Scoped calibration is separate. Distance was added in 1.5 and remains off for old saved sessions. Camera-free sessions, pause/end/finish, saved recovery and permission failure keep capture off or provide an explicit camera-free fallback. Session reminders follow the reviewed plan rather than the general rhythm; off-for-today still applies.
21. A delayed tick grants a full rest instead of consuming it in the background. Sleep gaps above 90 seconds or backwards clock changes pause the session rather than replaying a queue. Only one current water reminder is retained. Exercise guides use optional, in-memory upper-body movement cues; no exercise/repetition compliance claim or completion record is inferred from camera movement.
22. Background alerts use a normal topmost, non-focus-stealing app window independently of native Windows banners. WinRT ToastNotifier.Setting supplies confirmed block states; unknown is not treated as a block or successful delivery. Native notification failure leaves the popup active. No policy, Do Not Disturb or notification preference is changed. This cannot override Windows secure surfaces or every exclusive fullscreen application.
23. Signal confidence takes the weakest of actual head-angle, face framing, lighting/detail and available pose-landmark visibility signals. It is withheld for unreliable/stale frames and explicitly labelled a heuristic. Relative distance is the inverse calibrated face-scale ratio; unknown reference dimensions do not become invented centimetres. Live readings use a one-second, memory-only IPC channel instead of querying all event history every second.
